# Rulings of 29 September 2026

Meridian answered one question for every decision still open in either tracker
— Crystal's `open-issues.md` and Crystal React's `docs/open-issues.md`. Each
question offered its options with their consequences and a recommendation. This
file records the question, the options and the answer, so that the work built
from each can be read against what was actually decided rather than against a
summary of it.

The recommended option is marked **(rec.)**. Every answer below is Meridian's.

---

## Crystal

### D-21 · The button's hover

`crystal.reset` writes a hover (content shadow, brightness 1.04) that
`crystal.component` erases; Crystal's button renders no hover.

- Delete the reset rule — the resting Resin control already is the floating
  state, and the `hover` caustic is the pointer affordance **(rec.)**
- Make the hover real in `crystal.component` — a visible change to every button
- A hover token set, default none

**Ruled: delete the reset rule.** No visible change anywhere; the stylesheet
stops saying something it does not render.

### 4.4 · `.tiny-button` in `motion.css`

The preview's own class, carried by the library's stylesheet.

- Move it to the preview, then drop it from `motion.css` **(rec.)**
- Promote it to a documented Crystal class
- Leave it

**Ruled: move it to the preview.** (4.4's other half, `nav-link`'s material, was
settled by D-22.)

### D-26 (a) · Dock controls that are not buttons

`.cr-dock`'s control rules reach only `<button>`.

- Extend the control, selected, focus and forced-colours rules to `[role=tab]`,
  `label:has(input[type=radio])` (selected by `:checked`) and `a` (selected by
  `aria-current`), inside `:where()` so no existing rule's specificity rises
  **(rec.)**
- Buttons only, documented
- A `data-` attribute hook

**Ruled: extend through `:where()`.**

### D-26 (b) · Button groups and split buttons

Touching segments, square interior corners, pill outside, a hairline between.

- A grouped dock variant, `.cr-dock.grouped` **(rec.)**
- A different surface in the vocabulary
- Leave grouping to each library

**Ruled: a different surface**, named **`group`** (`.cr-group`) — chosen over
`segmented`, which would be confused with the segmented control (a dock, D-23),
and `joined`.

### D-25 (a) · A dialog that scrolls its own surface

- The surface stops scrolling; a `.cr-dialog-body` child scrolls with the Frost
  scrollbar and the edge fade, header and footer fixed **(rec.)**
- Keep the surface scrolling

**Ruled: scroll a body child.**

### D-29 (b) · `.cr-dialog`'s position

- Scope `position: fixed` to `dialog.cr-dialog`; elsewhere the class is material
  only and the host positions it **(rec.)**
- Give the class the offsets and margins to centre on any element

**Ruled: key it on `dialog.cr-dialog`.**

### D-25 (b) · An overlay inside a pane

A menu stepping down to Haze inside a Haze pane has no edge or shadow.

- Author a recessed overlay recipe: Haze with the `--cr-edge` rim and the content
  shadow **(rec.)**
- Overlays are Frost everywhere
- Overlays inside a pane are Resin

**Ruled: author the recessed overlay.**

### D-25 (c) · The preview vendors 2.0.0

- Bump the preview to the latest published core and re-capture its baselines on
  the runner, disclosing every changed frame **(rec.)**
- Point Crystal React's gates at the core it installs instead
- Both

**Ruled: bump the preview and re-baseline.**

### D-27 (a) · The count badge

- A compact count size, `.cr-resin-haze.count`: the inset scaled to the mark, no
  block padding, a circle that grows to a pill **(rec.)**
- A different surface
- Leave counts to each library

**Ruled: a compact count size.**

### D-27 (b) · The indicator's field glyphs

- Key the glyph rules on `.cr-field-shell` whatever its element **(rec.)**
- Key them on a `data-` attribute the field sets

**Ruled: any `.cr-field-shell`.**

### D-28 · Motion no component can play as written

Asked as: select every assignment that should come off the catalogue; any left
unselected would be honoured by growing the component instead.

- `page-in`/`page-out` off the navigation entries **(rec.)**
- `busy` off progress and the loader, with linear progress assigned
  `activity-travel` rather than `activity-turn` **(rec.)**
- `resin-confluence` off the floating action **(rec.)**
- `reaction` off the authored bubble and `slider-step` off the colour area,
  slider and wheel **(rec.)**

**Ruled: all five come off.** No component grows to honour them.

### D-29 (a) · The virtualizer listed twice

- Keep `virtualizer`, remove `virtual-scroller`; the count becomes 284 **(rec.)**
- Keep `virtual-scroller`, fold the other in; 284
- Keep both at 285, one marked as an alias

**Ruled: keep `virtualizer`.** The catalogue is 284 components.

### D-4 · The phone leg of `verify-scroll`

- A real Android phone over ADB, driven by Playwright, as a device leg of
  `verify-scroll`
- Close it as a known limit: a gutter is unobservable where scrollbars overlay
  **(rec.)**
- A manual on-device checklist per release

**Ruled: a real Android phone over ADB.** Meridian supplies the device.

### D-17 · The `forced-colours-dark` flake

- Hunt it now: dispatch the visual job repeatedly on the runner to force an
  occurrence and read the artifact; close on the evidence either way **(rec.)**
- Re-capture a differing frame and fail only if the same pixels differ twice
- Keep waiting

**Ruled: hunt it now.**

### Release

- Fold today's rulings into 2.3.0, which is unpublished **(rec.)**
- Ship 2.3.0 as prepared and today's rulings as 2.4.0

**Ruled: fold them into 2.3.0.** Once every gate is green the tag is pushed from
here — CI publishes with provenance and stages it — and Meridian approves the
staged release with `npm stage approve`. Crystal React (R-26) and the preview
(D-25 c) then adopt it.
