## Published as it stands

At Meridian's direction (3 October 2026) everything is published as it stands,
and any breaking change in Crystal 2.x will be fixed in Crystal 3.0 rather than
in a 2.x release. The 2.4.0 release notes and the changelog list the contract
changes that note covers.

- **Crystal React 0.1.0-alpha.1** is tagged (`v0.1.0-alpha.1`) with a GitHub
  prerelease, MIT licensed and no longer private. Its first npm publish has to
  be done by hand, because npm cannot attach a trusted publisher to a package
  that does not exist yet: from `crystal-react`, `pnpm run build`, then
  `npm publish` (`publishConfig` makes it public under the `alpha` tag; npm also
  points `latest` at a package's first version). Afterwards add a trusted
  publisher on npmjs.com and a tag-triggered publish workflow like core's, so
  later versions publish from CI with provenance.
- It needs a bundler; plain Node ESM cannot import it yet (R-30).
- **Crystal's own code has no licence statement.** `@crystal-ui/core` says "SEE
  LICENSE IN licenses", and that folder holds only third-party notices. Every
  published version so far is in that state. It is Meridian's to decide.

## How the work is done here

- **Measure before assigning** (CONTRACT §3). A surface enters a catalogue entry
  only after a component wearing it has been measured in a browser, computed
  values and not class names, and the extend-catalogue script cites the
  measurement. Read every property that matters: the first measurement of the
  toast's Haze fill checked the colour and the feather and missed that the
  layer was drawn at 4.5% opacity.
- **The task board.** Mark a built task by setting its `status` to `done` in
  `tasks.json`, then run `render-tasks.mjs`. Rulings are Meridian's alone and go
  append-only through `apply-rulings.mjs` (or the board's page); it regenerates
  the rulings record and the open-issues summary, and skips entries already
  moved to `closed-issues.md`. After any board change, run
  `pnpm run sync:slice-r` in crystal-react and commit the plan.
- **Test-run noise.** `npm test` in core rewrites the date in
  `validation/token-checks.json` and `core/docs/accessibility.md`; revert a
  date-only change. After adding contrast checks, run
  `node tools/build-reference.cjs` once more, because `npm test` builds the
  reference before it recounts the checks.
- **Crystal React's browser gates.** `verify:behaviour`, `verify:appearance`,
  `verify:targets`, `verify:materials` and `verify:theme` run against
  Storybook (`STORYBOOK_ORIGIN`, default 6006). Serve a built
  `storybook-static` with `node scripts/serve-static.mjs`, which answers Range
  requests; Python's `http.server` does not, and the caption checks then fail.
  `verify:materials` also needs crystal-preview served on 4321.
- **Generated files.** Never hand-edit `surface-recipes.json`, the catalogue's
  generated files, `parity.json` or `crystal-theme.css`; change the source and
  rebuild. `crystal-theme.css` has stayed byte-identical through all of this
  work (sha256 begins `6e5cec2e33fd`).
